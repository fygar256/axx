# axx — 汎用アセンブラ: 1 行書けば、どの CPU のアセンブラにもなる

axx は汎用アセンブラです。テキストファイルを 1 本書けば、どんな命令セットのアセンブラも手に入ります。

```
RET :: 0xc3
```

この 1 行だけで、x86\_64 の `RET` 命令のアセンブラとして完結しています。`命令の構文 :: エラー条件 :: 出力` という同じ形の行を積み重ねれば、Intel 4004 から AVX-512 付きの x86\_64、SVE/SME2 付きの AArch64 まで、実在の CPU のアセンブラになります。C++ も Scheme も、コード生成の段階も要りません。

- 作者: fygar256 (前川 田井介)
- ライセンス: MIT
- リポジトリ: [github.com/fygar256/axx](https://github.com/fygar256/axx)
- 名前の由来: **A**rbitrary e**X**tended **X** assembler

axx が*汎用*なのは、どのターゲットにも共通するひとつの仕組みで動くという意味です。アセンブラを、ISA ごとに書くプログラムから、ISA を記述するデータへと変えます。

## クイックスタート

```sh
git clone https://github.com/fygar256/axx.git
cd axx
make                                                   # caxx・paxx・axx をビルド
./axx patfile/z80.axx asmsrc/z80.s -v                  # Z80 のリスティング
./axx patfile/x86_64.axx asmsrc/hello.s -o out.o       # x86_64 の ELF オブジェクト
./axx patfile/8080toz80.axx asmsrc/hello8080.s -V      # 8080 から Z80 への翻訳
./bfsh/bf_x86_64_linux.sh run                          # Brainfuck でマンデルブロ集合を描く
```

コマンドラインは `axx <パターンファイル> <ソース> [オプション]` です。主なオプション:

| オプション | 出力 |
| --- | --- |
| `-b FILE` | フラットなバイナリイメージ |
| `-o FILE` | ELF32/64 の再配置可能オブジェクト（`-f 32` / `-f 64`、機種番号は `-m`） |
| `-g` | オブジェクトに DWARF の行情報を入れる |
| `-v` | アドレス・ソース行・出力バイトのリスティング |
| `-V` | 翻訳器（`.textmode`）向けのテキスト出力 |
| `-e` / `-E` / `-i` | ラベル表（TSV）の書き出し・読み込み |

`axx -h` で全オプションの一覧が出ます。各オプションの説明は `Technical_Manual_ja.md` にあります。

## axx のどこが違うか

### 1 命令 1 行、マニュアルからそのまま書き写す

構文・範囲の検査・出力が 1 行に収まります。8048 の例:

```
ADD A,R!n :: n>7;5 :: n|0x68
```

`add a,r1` は 0x69 を出し、範囲外のレジスタ番号はエラー 5 を報告します。パターンファイルはデータシートの命令表とほとんど同じ見た目になるので、読みやすく、直しやすくなります。

### トークナイザのない自由な構文

axx は 1 文字ずつ照合するので、文法はパターンの書き手が決めます。`MOV A,B` のような古典的な形はもちろん、`r1 = r2 + r3` のような代入形式の命令や、`{v0.4s}` のような ARM64 の記法も、特別な扱いなしにそのまま書けます。`.symbolc` / `.labelc` で識別子に使える文字を宣言できるので、`$v0` のような MIPS の名前もそのまま使えます。

### 順序に依存しない照合

当てはまるパターンの中から、axx は特異度スコアで最も具体的なものを選びます。特殊な場合を先に並べる必要がないので、何万行にもなるパターンファイルでも育てやすいままです。`.unordered` を使えば、指令の順序も自由になります。

### 三層構造: 宣言的な安全性と計算能力の両立

- **マクロ層**（`!def` / `!if` / `!while`）: 読み込み前にパターンやソースを生成します。
- **パターン層**: 宣言的な核です。チューリング完全ではないので、照合は必ず止まります。
- **ミニ言語**（`.func` / `.call`）: 式では書けない符号化を計算し、名前で呼び出します。

ミニ言語を使うと、AArch64 の論理即値命令群全体が 86 行のパターンに収まります。

### 機種を知らないコードからリンク可能な ELF を出す

`-o` は ELF32/64 の再配置可能オブジェクトを出し、そのまま GNU ld や ld.lld に渡せます。`-g` で DWARF を加え、`.cfi_*` で `.eh_frame` を作ります。ELF を書き出すコードには機種ごとの分岐がありません。再配置の型、REL/RELA、命令語の中のビット欄、`r_info` の並びは、すべてパターンファイルで宣言します。組み込みの 11 機種の表も、あらかじめ書いておいた宣言にすぎません。

### アセンブリ言語間の翻訳器

出力欄に文字列テンプレートを書いて `.textmode` を宣言すると、パターンファイルはソースからソースへの翻訳器になります。同梱の例:

- `8080toz80.axx`: Intel 8080 のソースを Z80 の記法へ
- `intel2att.axx`: x86-64 の Intel 構文を AT&T 構文へ（60 行が 3,437 パターンに展開されます）
- `a64tox64_axx.axx`: AArch64 のアセンブリを x86\_64 へ。axx だけで実行ファイルまで作れます

### VLIW、EPIC、任意のワード幅

`.vliw` 宣言で、Itanium 風の EPIC を含む VLIW 機を扱えます。1 ビットから 64 ビットまでのワード幅を `.bits::12` などで指定でき、ビットスライス機や 4 ビット機にも対応します。半精度から四倍精度までの浮動小数点即値は `!F` / `!D` / `!Q` で扱います。

### 有限静的変換で書ける ISA なら、どのプロセッサでも

命令型アセンブリ言語について、axx は *generic processor ISA*（汎用プロセッサ ISA）、つまりアセンブリから機械語への写像が**有限静的変換**であるプロセッサなら、どれのアセンブリでも処理できます。*静的*とは、各行の符号が、実行時の状態ではなく、アセンブル時に行のテキスト・パターンファイルの宣言・ラベルの値から決まることです。*有限*とは、命令の形が有限個で、1 行が有限個のワード列になり、符号化の計算が終わることです。それぞれの条件は axx の仕組みに対応しています。形ごとに 1 行のパターン、特異度スコア、`error_patterns`、符号化のための式とチューリング完全なミニ言語、そしてラベルに依存する長さのための緩和です。`Technical_Manual_ja.md` の 1.7 節に、この主張とチェックリストがあります。

### 形式的な基礎

`axxsemantics` は axx を表示的意味論で形式化しています。ソースから照合・環境・バイナリを経てオブジェクトに至る意味関数で、緩和はラベル環境の上の不動点として位置づけられています。

## 対応している ISA

`patfile/` には 61 本のパターンファイルがあります。主な ISA は外部の参照アセンブラとバイト単位で照合してあり、ELF 出力はそのままリンクできます。

| ISA | 範囲 | 照合相手 / リンク先 |
| --- | --- | --- |
| x86\_64 | x86\_64-v3、セグメント、AVX/AVX2、BMI1/2、x87、EVEX/AVX-512 | VEX/EVEX は llvm-mc 19 で照合、ld でリンク |
| AArch64 | A64 全体、Advanced SIMD、暗号、SVE/SVE2、SME/SME2 | llvm-mc 19 / ld.lld 19 |
| PowerPC64 | Power ISA v3.1（POWER10）、BE/LE、VMX、VSX、MMA、プレフィックス命令 | GNU as、GNU ld |
| RISC-V | RV64 全体: I/M/A/F/D/Q/Zfh/C、ビット操作、スカラー暗号、H、V 1.0 | llvm-mc、`ld -m elf64lriscv` |
| MIPS | MIPS I から MIPS64 Release 6、BE/LE、o32/n64、DSP、MSA ほかの拡張 | GNU as / llvm-mc、GNU ld |
| SPARC | V7/V8/V9、VIS 1–3、UA2005/2007、LEON | llvm-mc、ld.lld |
| レガシー | 68000、6809、6800、6502、Z80、8080、8051、8048、4004 | capstone、objdump、MAME、ucsim。境目とエラーのテストつき |
| 特殊 | VLIW、Itanium 風 EPIC、Brainfuck の仮想 CPU | 実装どうしで突き合わせ |

ARM（A32/T32）、RV32、32 ビット PowerPC のパターンファイルはこれからです。書式はすべて文書化されているので、誰でも書き始められます。

## 3 つの実装、1 つの仕様

axx には独立した 3 つの実装があり、同じ入力に対してバイト単位で同じ出力を出します。

| 実装 | ソース | 規模 | 備考 |
| --- | --- | --- | --- |
| Paxx（Python） | `axx.py` | 13,985 行 | 参照実装。新機能はまずここに入ります |
| Caxx（C） | `caxx.c` | 24,078 行 | 高速。約 24,000 パターンに対する x86\_64 の hello world が約 0.1 秒 |
| Faxx（Forth） | `faxx.fs`、`faxxsrc/`（69 ファイル） | 15,072 行 | gforth で動き、ccforth で実行ファイルにもできます |

C 版と Forth 版は独自の 256 ビット整数型を持っているので、式とミニ言語は Python 版とまったく同じように桁あふれします。

Faxx はリポジトリの最上位から動かします:

```sh
gforth faxx.fs patfile/z80.axx asmsrc/z80.s -b z80.bin   # gforth で動かす
make faxx                                                # または ccforth で ./faxx を作る
./faxx patfile/z80.axx asmsrc/z80.s -b z80.bin
```

ビルドは `build_ccforth.sh` が行います。[ccforth](https://github.com/ncw/ccforth) と C コンパイラが必要です。

### テスト

`test1` は、パターンファイルとソースの組をすべて caxx と paxx でアセンブルし（それぞれ 220 回）、結果を `cmp` で比べます。`-b` のイメージに加えて、ELF オブジェクト（`-o`、ELF64 と ELF32）、DWARF（`-g`）、リスティング（`-v`）、翻訳されたテキスト（`-V`）、標準エラーの診断も比べます。パターンファイルが拒むべき行を集めた `_err.s` と、範囲の境目の行を集めた `_edge.s` も含まれます。

2 つの実装は差分ファジングでも突き合わせています。そこで見つかった食い違いは `regress.axx` と `regress*.s` に残してあります。

## デモ

| コマンド | 結果 |
| --- | --- |
| `caxx patfile/x86_64.axx asmsrc/hello.s -o out.o` | `ELF 64-bit LSB relocatable, x86-64`。paxx と faxx も同じバイトを書きます |
| `bfsh/bf_x86_64_linux.sh run` | axx で作った Brainfuck インタプリタが `mandelbrot.bf` を描きます |
| `aarch64tox64/testrun.sh` | AArch64 のソースを axx で x86\_64 に翻訳し、axx でアセンブルし、ld でリンクして `mandelbrot.bf` を描きます |
| `caxx patfile/intel2att.axx asmsrc/intel2att.s -V \| as --64` | 翻訳された AT&T のテキストが、そのまま GNU as を通ります |
| `caxx patfile/8080toz80.axx asmsrc/hello8080.s -V` | CP/M の hello world を Z80 の記法で。ラベル・コメント・字下げはそのまま残ります |
| `caxx patfile/z80.axx asmsrc/z80.s -v` | アドレス・ソース行・出力バイトのリスティング |

`bfsh/` には CPU と OS ごと（Linux と FreeBSD の x86\_64、AArch64、PowerPC64、MIPS、RISC-V、SPARC）のスクリプトがあるので、`mandelbrot.bf` は qemu の上でも動きます。

## 関連するツールとの違い

axx は、宣言的な ISA の記述と、リンク可能な ELF の宣言的な記述を、1 つのファイルにまとめて持ちます。

多くの CPU に対応するアセンブラのほとんどは、各 CPU の知識を自分のソースコードに持っています。axx はその知識をすべてパターンファイルに移しているので、核は小さく、どのターゲットでも同じままです。CPU を足すときはテキストファイルを書くだけでよく、アセンブラを書き換えてビルドし直す必要はありません。

| ツール | ターゲットの足し方・記述のしかた | オブジェクト出力 | 向いている用途 |
| --- | --- | --- | --- |
| **axx** | 自由な構文のパターンファイル 1 本。ビルドし直し不要 | 宣言から生成する ELF32/64、DWARF、CFI | 歴史的な ISA、自作の ISA、珍しい ISA を、最初から最後まで読める記述から実際の OS へ持ち込む |
| GNU as | binutils の中に CPU ごとの C のコードを書き、ビルドし直す | ELF、COFF、Mach-O ほか | GNU の環境での実用ツールチェーン |
| LLVM MC | TableGen に加えて、手書きの C++ が相当量。ビルドし直す | ELF、COFF、Mach-O、wasm | 主流のアーキテクチャ向けの実用ツールチェーン |
| The Macroassembler AS、vasm | CPU ごとの C のモジュールを書き、ビルドし直す | AS: 独自形式（hex やバイナリに変換）。vasm: バイナリ、ELF、a.out ほか | 多くのレトロ CPU を、なじみのある 1 つの構文で |
| customasm | 宣言的な規則（Rust） | バイナリ、hexdump、intelhex などのダンプ形式 | ROM やエミュレータ向けの自作 CPU |
| Telemark TASM | 命令表 | hex 形式とバイナリ | 8 ビットのマイクロプロセッサとマイクロコントローラ |
| CGEN | Scheme で書く命令の意味 | binutils の一部を生成 | GNU binutils/GDB の組み込み向け移植 |

表のほかに、axx ならではの点が 2 つあります。

- **自作の CPU に、その日のうちにアセンブラができる。** FPGA のソフトコアや、紙の上にしかない教育用の CPU でも、命令表をパターンファイルに書き写せば、すぐにアセンブルでき、ELF のリンクまでできます。他のアセンブラでは、ここに最も手間がかかります。
- **アセンブラと翻訳器が 1 つの道具。** 出力欄にバイトの代わりにテキストを書けば、同じ仕組みがアセンブリ言語間の翻訳をします。8080 から Z80 へ、Intel 構文から AT&T へ、AArch64 から x86\_64 へ。

GNU as と LLVM MC は、大きなツールチェーンの中で特定の主流 CPU を深く最適化して支えるのに向いています。axx は別の軸で先を行っています。最初から最後まで読める記述から、どの CPU にも素早く届くことです。

LLVM の AsmMatcher は、Hexagon のニーモニックのない `r0 = r1` という構文のために専用の処理を必要としました。axx は最初から 1 文字ずつ照合するので、こうした構文も自然に書けます。

## 歴史

着想と名前、そして C による原型は 1986 年、作者が大学生のころ、アルバイト先の東京電子設計で生まれました。38 年後に当時のプログラムリストが見つかり、axx は Python で書き直されて 2024 年 4 月に公開されました。

その 38 年の間に VLIW、EPIC、8 ビット以外のワード幅、スケーラブルなベクトル拡張が現れましたが、axx は核の設計を変えずに、そのどれにも対応しています。最初のコミットは 2024 年 4 月 4 日、C 版は 2026 年 2 月、Forth 版は 2026 年 10 月に加わり、開発はいまも続いています。

## axx はこんな方に

- 好きなレトロ CPU や自作の CPU のために、本物の ELF を出すアセンブラがほしい方
- 珍しいターゲット向けにツールチェーンを作る、OS やブートローダの趣味の方
- 宣言だけでアセンブリ言語間の翻訳や移植をしたい方
- アセンブラとは本質的に何か、に興味のある方
- 大きな ISA のパターンファイルを AI の助けを借りて書きたい方。宣言的で機械的な書式は AI と相性がよいです（`axx_ai_pattern_guide_ja.md` を参照）

## 貢献

ARM（A32/T32）、RV32、32 ビット PowerPC のパターンファイル、それに構造化マクロや最適化は、貢献を心から歓迎している分野です。`RET :: 0xc3` という 1 行から始まる世界を、一緒に広げてください。
